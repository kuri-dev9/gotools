# gb64

`gb64` is the CLI frontend for the shared `pkg/b64drop` engine. Drop is the
default command.

```text
gb64 [options] <file>
gb64 [options] -n <stdin-filename>
gb64 drop [options] [file]
gb64 encode [file]
gb64 decode [file] [-o output]
```

The input is gzip-compressed once into a disk spool. If its final Base64 size
is within the threshold, gb64 emits one compatible B64DROP v1 block. Otherwise
it interactively emits v2 Chunks, one per ENTER key press.

```sh
gb64 sample.dat
gb64 drop sample.dat
cat sample.dat | gb64 -n sample.dat
gb64 --chunk-size 10M large.dat
gb64 --no-chunk large.dat
gb64 large.dat --chunk 8
gb64 large.dat --chunk 8 --verify-source
```

`--chunk-size` limits the unwrapped Base64 payload of each Chunk. Its initial
default is 5 MiB, exposed as `DefaultChunkPayloadSize`; it is not a universally
verified PuTTY-safe value. Adjust it after testing the actual terminal,
scrollback, and clipboard environment.

For regular files, compressed payloads are cached under the operating system's
user cache directory for seven days. `--chunk N` reuses cached gzip when source
path, size, mtime, manifest, and cache size match. It does not read or hash the
complete source by default. Add `--verify-source` to recalculate the original
SHA-256 before reuse. stdin Chunk retry is available only while the original
interactive process remains running.

Encode and decode are plain Base64 operations unrelated to B64DROP.

## Build

Linux, from the repository root:

```sh
make gb64
```

Windows, from the repository root:

```bat
WindowMakefile.bat
```

The Windows script builds `bin/gb64.exe`, `bin/gcurl.exe`, and
`bin/B64Drop.exe`. The Linux output is `bin/gb64`.
